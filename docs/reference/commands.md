# Commands

Every command is generated by the `specify` CLI from a `commands/<name>.md` file. For Claude Code the invocation is `/speckit-<extension>-<command>` (or `/speckit-<command>` for the core commands provided by the preset); other integrations use their own prefix for the same command IDs.

## Core commands (preset `central-workspace`)

Installed from `presets/central-workspace/`. Required in every workspace. The first seven replace the Spec Kit core commands of the same name; `review`, `verify` and `release` are additions.

| Command | Description |
| --- | --- |
| `/speckit-specify` | Create or refine traceable initiative requirements in the central workspace. |
| `/speckit-clarify` | Find and record missing initiative decisions without inventing answers. |
| `/speckit-plan` | Produce an implementation-ready technical plan under the selected initiative domain. |
| `/speckit-tasks` | Build a traceable task or story breakdown from an approved initiative plan. |
| `/speckit-analyze` | Analyze scope and tasks against source repositories and shared contracts. |
| `/speckit-implement` | Implement explicitly selected tasks in the resolved application repository. |
| `/speckit-converge` | Find remaining implementation gaps and append traceable work. |
| `/speckit-review` | Review initiative artifacts or an application diff against approved scope and evidence. |
| `/speckit-verify` | Verify completed implementation against requirements and record exact evidence. |
| `/speckit-release` | Prepare or execute an explicitly requested release stage with a named target. |

## Extension `technical-solution`

Installed from `extensions/technical-solution/`.

| Command | Description |
| --- | --- |
| `/speckit-technical-solution-setup` | Create the central workspace files (manifest, initiative registry, profiles) without overwriting anything. |
| `/speckit-technical-solution-run` | Start or resume an initiative lifecycle across common, Salesforce, MuleSoft and other installed domains. |
| `/speckit-technical-solution-review` | Review requirements, implementation evidence and cross-domain consistency of an initiative. |

## Extension `mulesoft`

Installed from `extensions/mulesoft/`. Artifacts go to the initiative root (`initiatives/<id>/mulesoft/` by default).

| Command | Description |
| --- | --- |
| `/speckit-mulesoft-specify` | Create MuleSoft requirements from the common initiative intent. |
| `/speckit-mulesoft-clarify` | Identify contract, runtime, ownership and evidence gaps. |
| `/speckit-mulesoft-plan` | Draft a MuleSoft technical plan grounded in app and contract evidence. |
| `/speckit-mulesoft-review` | Review app scope, contract provenance and consistency with common integration IDs. |
| `/speckit-mulesoft-tasks` | Create traceable MuleSoft implementation, verification and release tasks. |
| `/speckit-mulesoft-analyze` | Analyze selected MuleSoft apps and contracts against the initiative scope. |
| `/speckit-mulesoft-implement` | Implement explicitly selected MuleSoft tasks in a configured source repository. |
| `/speckit-mulesoft-qa` | Run planned MuleSoft checks and record results in the central initiative. |
| `/speckit-mulesoft-verify` | Review implementation and verification evidence against initiative requirements. |
| `/speckit-mulesoft-change` | Assess a request against the current MuleSoft initiative baseline. |
| `/speckit-mulesoft-pr` | Review MuleSoft changes and prepare repository-native review evidence. |
| `/speckit-mulesoft-deploy` | Deploy only to an explicitly requested MuleSoft target. |
| `/speckit-mulesoft-uat` | Prepare or record business UAT for MuleSoft requirements. |
| `/speckit-mulesoft-release` | Prepare a MuleSoft release record from approved evidence. |

## Extension `sf-workspace`

Optional add-on installed from `extensions/sf-workspace/` (`--with-sf-workspace`). Wrappers around the vendored SFSpeckit prompts for the extended stages; they extend the `salesforce` artifacts and never write the workspace constitution. Deploy, login and test commands in the prompts run only on an explicit request. Do not install together with the catalog `sf` extension.

| Command | Description |
| --- | --- |
| `/speckit-sf-workspace-setup` | Automated dependency checker and installer (sf, gh, sf-scanner). |
| `/speckit-sf-workspace-stories` | Generate Jira-ready developer stories with security matrices. |
| `/speckit-sf-workspace-analyze` | Pre-implementation analysis with mother story context and org drift detection. |
| `/speckit-sf-workspace-implement` | Implement a story file with auto-heal loop and scoring gates. |
| `/speckit-sf-workspace-change` | Handle mid-sprint requirement changes with impact analysis. |
| `/speckit-sf-workspace-qa` | Generate manual test scripts and run automated Apex/Jest tests. |
| `/speckit-sf-workspace-pr` | Prepare a PR with scoring gates and code review checklist. |
| `/speckit-sf-workspace-verify` | Generate formal Verification Evidence documents with coverage metrics. |
| `/speckit-sf-workspace-deploy` | Promote Salesforce code across environments (Dev to QA to UAT to Prod). |
| `/speckit-sf-workspace-score` | 555-point quality scoring dashboard across all stories in a feature. |
| `/speckit-sf-workspace-hotfix` | Emergency production bug fix workflow with fast-track deployment. |
| `/speckit-sf-workspace-regression` | Run full regression tests across all stories in a feature. |
| `/speckit-sf-workspace-release-notes` | Auto-generate release notes from completed stories and test results. |
| `/speckit-sf-workspace-uat` | Generate UAT scripts and manage business sign-offs. |

Argument hints are in each command file's frontmatter. The orchestrator `/speckit-technical-solution-run` accepts `<stage-or-full-cycle> <initiative-id-or-source> [domain] [repository-id-or-root]` with any further text taken as the title or request; stage commands take `<initiative-id>` first.
